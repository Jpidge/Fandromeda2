FANDROMEDA TESTING HISTORY
==========================

2026-09-19 — Canonical scoring engine, phase 1
------------------------------------------------
Implementation status: verified locally with
``python -m unittest discover -s tests -v``.

The authoritative Fantasy Football Coalition rules now live in
``fandromeda/scoring.py`` rather than being duplicated inside the application.
The module contains exact formulas for core non-PPR offense, long-touchdown
bonuses, return scoring, offensive fumble-return touchdowns, kicker scoring,
and D/ST scoring including all points-allowed tiers. The existing weekly
offensive-stat pipeline now calls this shared engine.

Test command:
    python -m unittest discover -s tests -v

Phase-2 limitation:
    Weekly player totals cannot identify long touchdowns, return events, or
    all K/DST events. Historical nflverse play-by-play will be loaded and
    aggregated before those event-specific fields are allowed into actuals,
    backtests, or projections.

2026-09-19 — Play-by-play scoring reconstruction, phase 2a
-----------------------------------------------------------
Implementation status: added; local test execution pending.

``fandromeda/pbp_scoring.py`` reconstructs a compact player-week event table
from nflverse play-by-play. It covers 40+ passing/rushing/receiving touchdown
bonuses, return yards/touchdowns, offensive fumble-return touchdowns, PATs,
and made field-goal distance. It rejects data without season/week and excludes
postseason plays. It does not yet alter production scoring: first inspect a
single cached season, then validate schema/event totals before integrating
those fields into historical actuals and retraining.

First controlled command:
    python index.py --build-scoring-events --season 2025

2026-09-19 — Play-by-play scoring reconstruction, phase 2b
-----------------------------------------------------------
Implementation status: added; local test execution pending.

Validated cached player-week event tables are now joined to weekly NFLverse
player statistics before the canonical scoring engine calculates actual
points. This updates scoring for available 40+ touchdown bonuses and return
events without inventing unavailable offensive fumble-return touchdowns.

Model implication:
    The historical targets have changed. Existing learned-weight and direct
    ML model files must be retrained, and the 2025 holdout must be rerun,
    before any new projection claims are made.

Artifact safety:
    Saved ML artifacts now record the scoring version. Models without the
    current ``ffc_yahoo_v1`` marker are deliberately not applied, preventing
    old target definitions from silently powering a newly scored dashboard.

Runtime improvement:
    Running ``--train-ml --learn-weights`` now builds the shared historical
    training table once, then fits both model layers from that same immutable
    in-memory table. It changes runtime, not the examples or model formulas.

2026-09-19 — First ML holdout validation
-----------------------------------------
Command:
    python gptindex.py --validate-ml

Test design:
    * Training seasons: 2018 through 2024
    * Untouched test season: 2025
    * Test examples: 17,376 player-week forecasts
    * Each historical projection uses only data available before the
      projected week. The target week's actual fantasy points are not used
      as an input feature.

Results:

    Model                                MAE   RMSE   Bias    Within 3   Within 5
    -----------------------------------  ----  -----  ------  ---------  ---------
    Baseline projection                  1.40   3.74  -0.20    85.2%      90.0%
    Machine Learned Weight Values        1.38   3.34  +0.05    84.7%      91.5%
    Machine Learned Points Projection    1.38   3.34  +0.06    84.0%      91.3%

Definitions:
    * MAE (mean absolute error): average distance between projected and
      actual fantasy points. Lower is better.
    * RMSE (root mean squared error): gives extra weight to larger misses.
      Lower is better.
    * Bias: average over- or under-projection. Near zero is better.
    * Within 3 / Within 5: percentage of projections within that many
      fantasy points of the actual result. Higher is better.

Interpretation:
    * Both ML approaches improved MAE slightly: 1.40 to 1.38.
    * Both ML approaches reduced RMSE from 3.74 to 3.34, about an 11%
      reduction in the effect of larger misses.
    * Both improved the within-5 rate. They trade a small reduction in
      within-3 rate for fewer larger errors.
    * The transparent learned-weight model and the more complex direct
      XGBoost model performed almost identically in this aggregate test.
      That is encouraging: the interpretable model currently earns its
      place without sacrificing measured accuracy.

Important limitation:
    These are aggregate results across player-weeks. Before relying on the
    result for every roster decision, test the same models separately for
    QB, RB, WR, and TE. An aggregate improvement can hide a weaker position
    group.

Dashboard correction made after this test:
    The live dashboard's plus/minus range was originally calculated around
    the baseline projection. When learned weights replaced the displayed
    projection, the range could remain centered on the old baseline. The
    range is now recalculated around the final displayed projection. This
    display correction does not change the holdout results above.

Next planned validation:
    1. Produce an offensive-only aggregate in addition to the position rows.
    2. Treat the corrected offensive and position results as the benchmark.
    3. Add one leakage-safe matchup feature group at a time.
    4. Re-run the same untouched-2025 test.
    5. Keep a new feature only when it improves relevant out-of-sample
       results without creating meaningful bias.
